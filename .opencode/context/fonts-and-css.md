# Fonts & CSS - Urutaú Limited

## Font pipeline

1. `googleFonts` plugin in `_config.ts` downloads **Lora** and **Intel One
   Mono** (roman + italic) from Google Fonts
2. Generates `@font-face` rules -> `output/urutau.css` (autogenerated, never
   edit)
3. `src/styles.css` is appended to `output/urutau.css` via
   `site.add("styles.css", "urutau.css")`

**Never write `@font-face` rules manually** in `src/styles.css`. The plugin
handles font loading.

## missing.css v1.3.0

Classless base styling: plain HTML elements styled automatically (headings,
tables, blockquotes, forms, etc.).

### Utility classes

Use literal angle brackets in class names:

```html
<p class="<h2>">Looks like an h2</p>
<span class="<small>">Small text</span>
<a class="<button>">Link styled as button</a>
```

### CSS variables (override in `:root`)

```css
:root {
    --main-font: "Lora", system-ui, sans-serif; /* Body text */
    --display-font: "Lora", system-ui, sans-serif; /* Headings */
    --secondary-font: "Lora", system-ui, sans-serif;
    --mono-font: "mono", monospace; /* Code blocks */
}
```

The three text variables are Lora; `--mono-font` uses Intel One Mono (see
`src/styles.css:19-25`).

## Custom CSS conventions

Located in `src/styles.css` (AGPL-3.0 licensed):

- Override missing.css defaults via CSS variable overrides and targeted rules
- `!important` is **valid** when overriding missing.css cascade — add a comment
  explaining why (example:
  `.pagefind-ui input { inline-size: 100% !important; }` because missing.css
  forces `20ch`)
- Dark/light themes via `@media (prefers-color-scheme: dark/light)`
- Font smoothing: `-webkit-font-smoothing: antialiased`,
  `text-rendering: optimizeLegibility`
- `p` and `a` are fixed at 1.13rem; `code` uses `clamp()`
- Pagefind search widget styled with CSS custom properties: `--pagefind-ui-*`

## Syntax highlighting

`codeHighlight` plugin appends atom-one-dark (dark theme) and atom-one-light
(light theme) to `output/urutau.css`. Base style reset:
`.hljs { background: unset; }`. `!important` not needed — specificity is
sufficient.

## When working with styles

1. Check missing.css docs first — utility classes or variables may already cover
   the need
2. Override via CSS variables in `:root` when possible
3. Add custom rules to `src/styles.css` last
4. Always add a comment explaining any `!important` usage
